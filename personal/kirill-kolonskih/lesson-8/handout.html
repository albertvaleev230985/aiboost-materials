Блок 1 · Подключение

Шаг 1. Проверь вход с ноутбука

Открой Codex на том Windows-ноутбуке и под тем пользователем, с которым проходил урок 7. Выбери папку проекта hermes-server и открой чат. Скопируй первый промпт целиком. Подставлять в него путь заранее не нужно.

Откуда возьмётся ключ?

На седьмом уроке Кирилл уже настроил вход. hermes-server — сохранённое короткое имя сервера. Когда Codex вызывает программу SSH, она берёт настройки этого имени из Windows и пробует войти. Открытая папка проекта сама по себе доступа не даёт.

Зачем этот промпт. Проверить вход с этого ноутбука до открытия Desktop. Команду запускает Codex. В ответе ты увидишь либо «Вход проверен», либо одно действие, для которого нужен Кирилл.

Вставь в Codex на ноутбуке Кирилла.

Помоги мне подключить Hermes Desktop на моём Windows-ноутбуке к моему серверу. Рабочая папка с прошлого занятия называется hermes-server. Сначала выясни, может ли этот ноутбук войти по ключу. Я пока ничего не ввожу вручную.

1. Выбери тот же SSH-клиент и пользователя Windows, что у Hermes Desktop. Учти настройку desktop.ssh_path, если она задана. Обычно это встроенный Windows OpenSSH. Если ты работаешь в WSL, используй клиент Windows. Если у тебя нет доступа к нему или к сети, скажи, как разрешить эту конкретную проверку или какую одну команду выполнить в PowerShell.
2. Проверь сохранённое имя hermes-server. Через ssh -G hermes-server посмотри фактические адрес, имя пользователя, порт и пути IdentityFile. У Windows обычный файл настроек — %USERPROFILE%\.ssh\config. Ключ также может быть стандартным или уже загруженным в ssh-agent. Не открывай содержимое ключей. Если адрес не определён, возьми подтверждённые несекретные данные из карточки проекта, если она есть, либо спроси у меня адрес, пользователя и порт из панели хостинга.
3. Когда подтверждена цель, выполни тем же клиентом: ssh -o BatchMode=yes -o PreferredAuthentications=publickey -o StrictHostKeyChecking=yes -o ConnectTimeout=8 hermes-server "echo HERMES_SSH_OK". При отсутствующем имени используй подтверждённые адрес, пользователя и порт. Успех — код 0 и ответ сервера HERMES_SSH_OK.
4. Если сервер отверг ключ, спроси: «Где лежит закрытый SSH-ключ от этого сервера? Пришли только путь через Проводник → Копировать как путь». Проверь указанный файл с -i и путём в кавычках. Если ключ запаролен, подскажи, как Кириллу разблокировать его локально через ssh-agent. Если файла у меня нет, остановись и скажи, какой доступ к панели хостинга нужен для восстановления. При тайм-ауте проверь доступность адреса и порта. При неизвестном или изменившемся ключе самого сервера сначала попроси сверить его отпечаток через консоль хостинга. Секреты в чат не проси.
5. Для поля SSH host в приложении подготовь точные данные. Если вводится пользователь@адрес:порт, проверь именно этот вход командой ssh с -p и теми же защитными параметрами, без разового -i. Если не сработало или имя hermes-server ещё не настроено, предложи точечную правку SSH-конфига для этой машины. Покажи правку, дождись моего согласия, сделай резервную копию и повтори оба теста.
Верни одну из двух фраз: «Вход проверен», затем проверенные имя подключения и значение SSH host, или «Нужно от Кирилла», затем одно конкретное действие. Не устанавливай программы и не меняй сервер.

Если появилось «Вход проверен». Сохрани строку SSH host. Это адрес, который понадобится в приложении. Переходи к следующей кнопке.

Если Codex попросил путь. Кирилл открывает в Проводнике папку со своим закрытым ключом, нажимает на файл правой кнопкой и выбирает «Копировать как путь» (иногда в «Показать дополнительные параметры»). В ответ Codex вставляет только скопированный путь. Сам файл остаётся на ноутбуке.

Файл с окончанием .pub — открытая часть ключа. Текстовый файл с логином и паролем от хостинга — данные для входа в панель. Если на руках только один из этих файлов, ответь Codex «закрытый ключ найти не могу» и дождись инструкции по восстановлению доступа.

Что означают SSH, IdentityFile и отпечаток

SSH — программа для входа на сервер. IdentityFile — настройка, которая указывает ей путь к ключу. ssh-agent — программа на компьютере, которая может держать ключ разблокированным. Отпечаток сервера помогает проверить, к какой машине ты подключаешься. Если SSH сообщает, что отпечаток изменился, сверь его в консоли своего хостинга до продолжения.

Шаг 2. Найди профиль Telegram-бота

Когда вход проверен, отправь своему боту Проверка Desktop. Дождись ответа и вставь второй промпт в тот же чат Codex.

Зачем этот промпт. На сервере может работать несколько помощников. Свежее сообщение поможет найти профиль Кирилла — набор настроек именно его помощника. Ещё узнаем, где запущен Hermes и какая модель выбрана.

Вставь в Codex на ноутбуке Кирилла.

Продолжаем в том же чате. Используй проверенное подключение из предыдущего ответа. Я только что отправил своему Telegram-боту «Проверка Desktop» и получил ответ.
1. Узнай версию Hermes на сервере и полный путь к исполняемой программе hermes. Проверь запуск по этому пути с --version. Уточни версию Desktop на ноутбуке, если она доступна.
2. По служебным данным свежего Telegram-сеанса установи, какой профиль его обслужил. Если ботов несколько, спроси публичное имя моего бота. Другие переписки не открывай. Если привязка не видна, так и скажи.
3. Для этого профиля посмотри провайдера и основную модель. Если видна модель именно этого Telegram-сеанса, укажи её отдельно.
Выдай карточку для урока: SSH host из нашей проверки, Hermes path, имя профиля и чем оно подтверждено, основная модель и модель Telegram-сеанса. Неизвестные поля подпиши «не подтверждено». Ничего не перенастраивай, не выводи ключи и токены.

Что показать Кириллу. В ответе есть адрес сервера, путь к Hermes и имя профиля с подтверждением. Если связь с Telegram ещё не подтверждена, имя первого в списке агента ничего не доказывает.

Шаг 3. Подключи Desktop к серверу

Hermes Desktop — окно управления на ноутбуке. Можно открыть его и всё ещё работать с локальной установкой. Поэтому сначала явно выбираем машину.

  1. В Hermes Desktop открой Settings → Gateways («Настройки → Подключения»). На Windows в версиях с палитрой команд можно нажать Ctrl+K и ввести Gateways.
  2. Посмотри список зарегистрированных подключений. Сервер Кирилла уже есть — выбери его и нажми Test. Если его нет — Add connection → SSH.
  3. Для нового подключения введи SSH host (куда подключаться) и, если поле предусмотрено, Hermes path (где на сервере установлена программа). Скопируй значения из карточки Codex. Если в карточке указано короткое имя, а форма требует адрес и порт, вернись в тот же чат и попроси проверить вход с точным адресом из формы. Порт и имя пользователя бери из проверки. Назови подключение понятно, например «Сервер Кирилла». Сохрани и нажми Test.
  4. Если видишь This device / Local, это ноутбук. Выбирай зарегистрированное подключение к серверу. Приглашение выбрать модель на приветственном экране можно пропустить.

Проверка на экране. Проверка нужного подключения успешна. В версии из предыдущего урока это надпись Reachable — «сервер доступен».

Если не совпало. Покажи Codex точный текст ошибки теста и версию приложения. Если требуется только подготовить поля SSH, ниже есть подсказка по полям подключения. Повторная установка Гермеса для этого шага не требуется.

Блок 2 · Управление агентом

Шаг 4. Открой своего агента

Выбор сервера отвечает на вопрос «где он работает?». Выбор профиля — «кто из агентов на этом сервере мне нужен?». Сеанс — отдельный разговор с выбранным агентом.

  1. Открой слева Sessions / Сеансы. В переключателе подключений выбери сервер Кирилла. Он показывается при нескольких зарегистрированных подключениях.
  2. В соседнем списке профилей выбери точное имя из карточки Codex. Когда полоса профилей скрыта, в актуальном интерфейсе выбор доступен также через Profiles в строке состояния. Если имя встречается дважды, решающим будет название сервера.
  3. Открой новый сеанс выбранного профиля и отправь «Ответь: на связи». Покажи выбранную машину и имя профиля рядом с разговором. Список старых сообщений может отличаться от Telegram, потому что это другой сеанс.
  4. Вкладка Bots / Боты — дополнительный вид с карточками агентов. Имя Telegram-бота и его фотография могут там не появиться. Связь устанавливаем по серверу, профилю и свежему сообщению из шага 1.

Проверка на экране. Кирилл сам показывает совпадение двух значений с карточкой: нужный сервер и имя профиля. Новый разговор получил ответ.

Если не совпало. Если есть только Local, вернись в Gateways. Если сервер уже выбран, но нужный профиль отсутствует, сверь список профилей на сервере с Codex. Создание одноимённого профиля даст другого агента.

Шаг 5. Сверь модель в двух окнах

Профиль — сам помощник с его правилами и доступами. Модель — то, что формирует ответ. У профиля есть основная модель, а отдельный разговор может пользоваться другой.

  1. Telegram. В чате с этим ботом отправь /model без аргументов. Прочитай отмеченного провайдера и текущую модель, если версия их показывает. Провайдер — сервис, через который Гермес получает ответы модели. Для просмотра не выбирай другую модель. Если меню не показывает текущую однозначно, используй /status или сведения сеанса из шага 1.
  2. Desktop, основная модель. На сервере Кирилла открой Settings → Model → Main model. Если есть Applies to («Для какого профиля»), укажи профиль из карточки. Прочитай провайдера и имя модели. При совпадении ничего менять не нужно.
  3. Desktop, текущий разговор. Вернись в сеанс того же профиля. У поля сообщения открой название модели. Сравни провайдера и точное имя модели с Telegram. Для вашего занятия выбирайте тот же вариант в этом разговоре, если ранее здесь выбрали другой.
  4. Если нужна другая основная модель для будущих разговоров. В настройках нужного серверного профиля выбери подключённого провайдера и модель, нажми Apply. Если нужного провайдера ещё нет, сначала Settings → Providers в том же профиле: владелец подключает свой аккаунт или вводит ключ в форме. Уже работающий вход из урока 7 сначала проверяем.
  5. После осознанной смены основной модели проверь её в новом сеансе Desktop и новом разговоре Telegram (если нужно начать заново, сначала сохрани нужный контекст). У старого разговора может остаться ранее выбранная модель.

Проверка на экране. На экране сопоставлены три строки: основная модель профиля, модель в Telegram, модель разговора Desktop. Для демонстрации оба разговора показывают одну пару «провайдер + модель».

Если не совпало. Ответ агента на вопрос «какая ты модель?» не является настройкой. Если нужной модели нет, проверь, что выбран тот же сервер, профиль и аккаунт провайдера. Не назначай похожую модель только по отображаемому названию.

Шаг 6. Посмотри навыки и расписание

Инструмент — доступное действие, например чтение файла. Навык — инструкция, как выполнять задачу. Задание по расписанию — работа, которой уже назначили время.

  1. Что ему разрешено. Открой Capabilities / Возможности и настройки инструментов (Tools / Toolsets, в некоторых версиях Tools & Keys). Выбери нужный профиль в фильтре. Покажи один действительно включённый инструмент.
  2. Какие у него навыки. В разделе Skills / Навыки открой список установленных. Покажи название и назначение одного включённого навыка. Предложения установить новый навык находятся отдельно.
  3. Что он делает сам. Через меню или Ctrl+K найди Scheduled Jobs / Cron («Задания по расписанию»). В режиме Bots повторяющиеся задачи могут называться Routines. Выбери профиль Кирилла, отключи фильтр «Все профили», если он включён.
  4. Открой существующее задание и посмотри, включено ли оно, когда назначен следующий запуск и есть ли результат последнего. Если список пуст, так и скажи: «Пока этому агенту не поручили ничего по расписанию».

Проверка на экране. Кирилл показывает инструмент, навык и фактический список заданий своего профиля. Если список пуст, это тоже установленный результат.

Если не совпало. Если раздела нет в этой версии, открой поиск разделов. Для сверки попроси Codex в прежнем чате только перечислить доступные инструменты, включённые навыки и задания этого серверного профиля. Не запускай и не меняй задания во время экскурсии.

По желанию · Покажи, где создать второго агента

Открой форму, чтобы показать принцип. Нажимай «Создать» только если Кирилл хочет оставить на сервере второго помощника.

  1. Открой Bots → New Agent («Боты → Новый агент»). Дай отдельное имя, например «Редактор», и одну задачу: «Готовит краткие итоги встреч».
  2. Посмотри Create on («Где создать»). При нескольких подключениях выбери сервер Кирилла. Когда подключение одно, поле может быть скрыто — сначала установи, к какой машине подключён Desktop. Если место создания неясно, оставь форму без сохранения.
  3. В Advanced можно выбрать Fresh profile (чистый профиль), модель, навыки и инструменты. Для учебного профиля выключи Copy API keys from the main profile / Share keys & accounts, если такой переключатель есть: он может передать новому агенту доступ к рабочим аккаунтам. Если состав доступов неясен, остановись на форме.
  4. При создании на выбранном сервере профиль появляется сразу там. После создания проверь, что он виден под сервером Кирилла, открой его чат. Если модель требует отдельного входа, для проверки создания достаточно увидеть профиль на сервере; тестовый ответ проверяют после подключения разрешённого аккаунта. Первый профиль по-прежнему должен быть доступен.

Проверка на экране. В списке того же сервера видны два разных профиля. Если вы только показали форму, второй профиль ещё не создан.

Если не совпало. Отдельный агент в Desktop может работать без Telegram. Для отдельного Telegram-бота нужен собственный бот и отдельное подключение к его профилю. Токен действующего бота повторно не используйте.

Проверка перед работой с памятью

Попроси Кирилла на минуту взять управление.

«Покажи свой сервер, профиль агента и выбранную модель. Какой навык ему доступен? Есть ли у него дела по расписанию?» Затем вернись в профиль, который отвечает в Telegram. С ним будем работать в третьем блоке.

Блок 3 · Общая память

Как устроена общая память

Один пример на весь блок: Кирилл кладёт в папку правила учебной встречи. Гермес читает их и рядом оставляет отдельную заметку.

Ноутбук. Хранилище — обычная папка. Codex по твоему поручению создаёт в ней файл. Obsidian открывает ту же папку и показывает файл как заметку.

Папка на ноутбуке ↔ Syncthing ↔ папка на сервере. Syncthing переносит изменения в обе стороны. Гермес читает и пишет в серверной папке. Когда приходит новая запись, её можно открыть в Obsidian.

Что показать. Два файла рядом: исходную памятку и заметку, которую записал агент. У каждого файла видны название и содержимое.

Зачем. Этот запрос показывает, что именно будет синхронизироваться. Если обмен уже настроен, используйте существующую пару папок.

Вставь в Codex.

Слова этого шага

GitHub, репозиторий и скрипт
GitHub — сервис для хранения проектов. Репозиторий — конкретный проект с кодом и историей изменений. Скрипт — программа, которая выполняет последовательность действий.
GitHub Actions, workflow и cron
GitHub Actions умеет запускать задания. Workflow — файл с описанием такого задания. Cron задаёт время повторения. В исходном расписании время может быть указано по UTC — общему мировому времени.
Секреты и токены
Данные для доступа к сервисам. Когда нужен секрет, Кирилл вводит его через согласованный защищённый способ. Значения не вставляют в переписку, заметки или код проекта.
Разобрать команды и имена файлов
Клонировать, gh auth login, коммит
Клонировать — создать локальную копию проекта. gh auth login — команда для входа в GitHub. Коммит сохраняет версию изменений в истории проекта.
.github/workflows, ~/.hermes/scripts, зависимости
Первая папка содержит задания GitHub, вторая указана в исходном промпте для скриптов Гермеса. Зависимости — дополнительные программы или библиотеки для запуска. Отдельное окружение держит их отдельно от других задач.
.env и права 600
Файл .env хранит настройки программы. 600 — режим Linux, при котором обычный доступ к чтению и записи файла есть только у владельца.
Прокси, socks5h, логи
Прокси — посредник для сетевого соединения. socks5h указывает, что имя сайта определяет прокси. Логи — служебные записи программы о её работе.
cron create, list, run, ID и --deliver telegram
Create создаёт расписание, list показывает список, run запускает задание сейчас. ID — его идентификатор. Параметр --deliver telegram указывает, куда доставить результат.
Сборка и GitHub Pages
Сборка готовит из исходных файлов работающий результат. GitHub Pages публикует сайт из проекта. Такие задачи остаются на GitHub, если результат нужен именно там.
