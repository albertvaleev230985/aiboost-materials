GitHub: страница уходит в интернет

Визитка и приложения из домашки живут у вас на компьютере: открыть их можете только вы. Сегодня одна просьба Codex, и у страницы появляется ссылка, которая открывается с любого телефона.

GitHub это склад для проектов: хранит вашу папку и каждую её версию. GitHub Pages это витрина при складе: показывает папку как сайт по ссылке. Бесплатно.

  1. Аккаунтgithub.com → Sign up. Почта, пароль, имя латиницей, проверка «я не робот», код из письма. Телефон не нужен. Удобнее с включённым VPN и на почту Gmail.

  3. КодCodex покажет одноразовый код и адрес. Открываете адрес в браузере, вводите код, нажимаете Authorize. Пароль от GitHub ему не даёте.
  4. «Да»Он покажет список файлов, которые уйдут в интернет. Прочитали, ответили «да».
  5. СсылкаЧерез одну-три минуты он даст ссылку. Откройте её с телефона.

Лестница: от промпта к плагину

Четыре слова, которые все путают: промпт, навык, коннектор, плагин. Агент это новый сотрудник, а эти четыре слова отвечают на вопрос, что ему дали.

Ступень 1 · ПромптРазовая просьба, «что хочу». Живёт в одном запросе, каждый раз объясняете заново.
Ступень 2 · НавыкРегламент одной операции, «как делать». Записали один раз, агент берёт его сам.
Ступень 3 · КоннекторПропуск к программе: почта, диск, календарь. Даёт руки, но не «как».
Ступень 4 · ПлагинСтартовый набор отдела одним пакетом: навыки, коннекторы, команды.

Одна заявка, четыре агента

Клиент пишет: «Сколько стоит шкаф 2,4 метра и когда сможете поставить?»

Только промптВы сами копируете письмо в чат и каждый раз объясняете, как отвечать.
Плюс навыкАгент знает ваш регламент ответа и прайс. Письмо всё ещё приносите вы.
Плюс коннекторАгент сам видит письмо в почте и готовит ответ по регламенту.
ПлагинНавыки и коннекторы целого отдела ставятся одной кнопкой.
Навык и коннектор не путаем. Навык говорит «как делать», но доступа ни к чему не даёт. Коннектор даёт «руки», но не «как». Плагин приносит навыки, коннекторы и команды одним пакетом.

Под капотом: API и MCP

Перед Дипресёрчем два слова, без которых непонятно, зачем нужны ключи: API и MCP. Представьте ресторан.

РесторанЭто программа: почта, карты, поисковый сервис.
Парадный входСайт и кнопки. Для людей: зашли, сели, заказали.
Служебный вход · APIДля программ и агентов. Открывается ключом. Ключ получает человек, один раз.
MCPОбщий стандарт пропусков: с ним агент одинаково заходит в служебные входы разных заведений.

Где здесь человек. Служебный вход открывается ключом: длинной строкой символов, которую сервис выдаёт после регистрации. Ключ получаете вы, один раз. Дальше агент ходит сам. Ключ это как пароль от квартиры: у кого ключ, тот и заходит от вашего имени.

MCP и API не путаем. API это служебный вход самой программы, открывается ключом. MCP это общий стандарт пропусков для агентов. Если программа пускает только по ключу, ключ API лежит в настройках пропуска.

Коннектор это пропуск к программе (почта, диск, календарь). Даёт «руки», но не «как». Внутри это MCP. В меню Codex коннекторы называются «приложения».

Вы это уже видели на занятии 5. Мастер-промпт поставил плагин Superpowers (набор навыков) и три сервиса по стандарту MCP: Context7, Sequential Thinking, Playwright.
