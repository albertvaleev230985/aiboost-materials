Ваш проект

Два живых случая. Каждый выбирает один экран.

Запишите одно действие, ожидаемый результат и то, что происходит на самом деле.

ПромптКуда: Codex · новый чат в рабочей папке проекта

Найти точку проверки

Открой мой учебный проект. Уточни, какое одно основное действие я сейчас хочу довести до рабочего результата. Найди его в приложении и зафиксируй в трёх строках: что нажимаю, что ожидаю увидеть, что вижу сейчас. Если приложение ещё не открывается, укажи последний проверенный шаг и предложи одно действие, после которого можно продолжить. На этом этапе только диагностика. Файлы оставь без изменений.

Итог Одна карточка, по которой другой человек может воспроизвести проблему.

19:15–20:00

Свой стиль

Карточка стиля и один экран до и после.

Установщики есть для macOS и Windows. На Linux можно использовать подготовленную копию ведущего или собрать приложение по инструкции проекта. Скачать Open Design. Откройте Home, выберите Prototype, нажмите + и добавьте снимок исходного экрана. Вставьте задание «Применить стиль к одному экрану» в большое поле и нажмите стрелку справа. Скачать учебный исходный экран. Посмотреть экран из официального обзора.

ПромптКуда: Codex · новый чат со своим брендбуком или снимком продукта

Собрать карточку стиля

Я оформляю один экран своего приложения. Прикладываю страницу брендбука или пример своего оформления. Выпиши три цвета с назначением (фон, текст, активное действие), шрифт для интерфейса и правило для голоса продукта. Для тона покажи пример короткой подписи на кнопке. Отметь, что взято из материала и что ты предлагаешь на выбор. Если у меня пока нет брендбука, используй учебную карточку: фон #F4F7F5, текст #18211D, акцент #91512D, системный шрифт без засечек для кнопок, короткие спокойные подписи. Для фильтра предложи одно изменение по карточке. Жди, пока я выберу.

Итог Три цвета с назначением, шрифт, тон и одно правило для выбранного элемента.

ПромптКуда: Open Design · проект Prototype, приложите снимок «до» и карточку стиля

Применить стиль к одному экрану

Работай с прикреплённым снимком моего приложения и карточкой стиля. Укажи одно действие, которое человек должен заметить первым. Примени одно правило брендбука к выбранному элементу, сохрани структуру, подписи и остальные действия. Создай открывающийся макет на ширине 390 px. Скажи, где я могу вручную поменять выбранное свойство. Сохрани исходную версию отдельным файлом.
Учебный пример для показа: над списком заявок стоят «Только открытые» и «Все». Активная кнопка по брендбуку медная #91512D с белым текстом. Поменяй только фон активной кнопки. В списке есть «Запрос на расчёт» (открыта) и «Согласовать сроки» (завершена). Оставь переключение рабочих состояний. Для своего проекта замени учебный пример моим элементом и правилом.

Итог Макет на 390 px и одна видимая правка по правилу из брендбука.

Помощники

Разовый критик и сохранённая роль для проверки.

Субагент выполняет отдельное поручение в своей ветке.

Навык задаёт порядок работы. Плагин упаковывает возможности для установки.

Для роли Codex нужны три поля TOML: name, description и developer_instructions. Модель можно указать для отдельной роли. Разрешения действуют из основного чата.

ПромптКуда: Codex · чат с исходным экраном, макетом и карточкой стиля

Позвать одного критика

Запусти одного отдельного субагента как критика интерфейса. Передай ему два снимка моего экрана, ширину 390 px и выбранное правило брендбука. В учебном примере правило такое: активная кнопка медная #91512D с белой подписью. Пусть укажет один конкретный элемент и скажет, какое действие человек видит первым и соблюдено ли правило. Точный цвет можно подтвердить по стилю в коде. Когда доступны лишь снимки, пусть укажет предел проверки цвета и поведения. Дождись ответа и покажи его отдельно. Файлы не меняй. Решение о правке оставь мне.

Итог Отдельный помощник возвращает одно наблюдение, которое можно проверить на экране.

ПромптКуда: Codex · новый чат в учебной папке проекта

Сделать своего проверяющего

Создай в этой рабочей папке роль Codex для приёмки интерфейса. Имя design-checker, путь .codex/agents/design-checker.toml. Если файл уже есть, покажи его и дождись согласования, прежде чем менять.

Заполни поля name, description и developer_instructions. Роль работает по одной странице и одному сценарию за вызов. Проверяет, видит ли человек следующее действие на узком экране. Для каждого замечания возвращает место, шаг, ожидаемый и фактический результат. Если браузер или экран недоступны, обозначает, какая часть осталась без проверки. Инструкция роли: файлы проекта не менять.

Проверь, что файл читается как TOML и в нём есть все три поля. Покажи путь и фразу для вызова по имени в новом чате.

Итог Файл роли в проекте. В следующем чате помощник запускается по имени.

ПромптКуда: Codex · новый чат в той же папке проекта

Вызвать сохранённую роль

Запусти сохранённого субагента design-checker для экрана списка заявок. На ширине 390 px найди, понятно ли пользователю, как показать открытые заявки. Проверь только этот сценарий, файлы оставь без изменений. Дождись ответа помощника и покажи отдельно: где он проверял, что нажал и что увидел. Если визуальный прогон недоступен, скажи, на каком шаге остановился.

Итог и домашка

Проверка на 390 px и результат для сдачи.

Дома откройте копию своего проекта. Сохраните снимок на 390 px, примените одно правило карточки стиля, снимите тот же экран ещё раз. Вызовите проверяющего по промпту ниже. В чат потока отправьте оба снимка и две строки: что изменили и как проверили фильтр. Для макетов укажите результат визуальной проверки.

ПромптКуда: Codex · новый чат в учебной копии приложения или с двумя макетами

Сравнить до и после

Запусти сохранённого субагента design-checker для обновлённого экрана списка заявок. Если правка уже применена в учебной копии, открой экран со списком на ширине 390 px. Проверь две учебные заявки: одну открытую и одну завершённую. Нажми «Только открытые» и убедись, что осталась только открытая. Нажми «Все» и проверь, что обе снова видны. Верни «Только открытые»: снова должна остаться одна.

Если есть только два макета, сравни расположение и заметность переключателя на ширине 390 px. Верни две строки: что стало понятнее и что проверено — вид в макете или действия в браузере. Файлы оставь без изменений. Сверь также одно правило моей карточки стиля. В выводе назови это правило и элемент, к которому оно применено.

Итог Одна фраза о том, что стало понятнее, и статус проверки: макет или рабочий экран.

Верни «Только открытые»: снова должна остаться одна.

Если есть только два макета, сравни расположение и заметность переключателя на ширине 390 px. Верни две строки: что стало понятнее и что проверено — вид в макете или действия в браузере. Файлы оставь без изменений. Сверь также одно правило моей карточки стиля. В выводе назови это правило и элемент, к которому оно применено.
