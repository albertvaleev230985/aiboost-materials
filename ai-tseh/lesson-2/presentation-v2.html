Локальный черновик

localhost это адрес проекта на твоём компьютере. Пока локальный сервер запущен, ты видишь результат в браузере. Выключил компьютер, и ссылка мертва.

localhost нельзя отправлять клиенту, другу или в общий чат как публичную ссылку.
У тебя открылосьэто ещё не значит, что откроется у других
Нужен запусксервер или preview работает на твоём компьютере
Публичность позженачинается после деплоя на хостинг
Проверяем до публикациисначала локально, потом наружу
Сервер и хостинг

Чтобы сайт увидели другие, ему нужно место в интернете

Серверотдаёт сайт

Компьютер или облако, которое отдаёт сайт, когда человек открывает ссылку.

  • Должен быть включён и доступен из интернета
  • Отдаёт браузеру страницы, стили и файлы
  • Для реальных данных нужна аккуратная настройка
Хостингместо для сайта

Площадка, где проект размещается, собирается и становится доступен другим.

  • Vercel и GitHub Pages это хостинги
  • После деплоя появляется публичная ссылка
  • Работает без твоего компьютера, круглосуточно
Статика

Статика это готовые файлы, сервер ничего не считает

Из чего состоит

Статический сайт это набор готовых файлов. Сервер просто отдаёт их человеку как есть, ничего не вычисляя.

index.htmlтекст и структура страницы
styles.cssвнешний вид: цвета, отступы, шрифты
script.jsповедение, и работает оно уже в браузере посетителя

Бытовая аналогия: статика это распечатанное меню, его печатают один раз и показывают всем одинаковое. Динамика это повар, который готовит блюдо под конкретный заказ.

Что из этого следует

Все посетители видят одно и то же, персонально ничего не меняется
Ничего не запоминается между визитами, кроме того, что осталось в браузере самого человека
Нет личных кабинетов и общей базы, потому что хранить негде
Для первой версии это не недостаток, а защита: нечего утечь и нечего сломать
Первая версия делается статикой специально. База появляется, когда реально надо хранить заявки, клиентов или заказы.
Сборка

Сборка это когда исходники превращают в готовые файлы

Пока проект это три файла, его можно отдавать как есть. Но как только появляются React, Next или Vite, браузеру исходники не скормишь: их сначала надо собрать. Разница между площадками в том, кто эту работу делает.

Сегодня у насчистая статика: три файла, сборка не нужна, площадка отдаёт их как есть.
Дальше на курсепоявится проект посложнее, и его перед показом надо будет собирать.
Кто соберётVercel определяет тип проекта и собирает сам. GitHub Pages этого не умеет.
Пишешь исходники. Сборка делает из них готовые файлы. Деплой выкладывает их в интернет.
Git

Git это история сохранений, а не облако и не сайт

git status

показывает, что изменилось в проекте

git add

выбирает изменения для сохранения

git commit

создаёт понятную точку сохранения

Commit сохраняет. Push отправляет. Deploy публикует.

У коммита есть подпись, и она должна говорить, что изменилось. «Добавил кнопку написать в Telegram» это подпись. «Правки» и «fix» это не подпись.

Главная путаница

GitHub и Vercel делают разную работу

GitHubхранилище кода

Хранит код, историю изменений и сам репозиторий.

  • Показывает, какие файлы есть в проекте
  • Хранит всю историю коммитов
  • Сам по себе сайт публичным не делает
Vercelпубликация сайта

Берёт код из GitHub, собирает проект и отдаёт сайт по ссылке.

  • Создаёт выпуск из репозитория
  • Выдаёт публичную ссылку
  • Обновляет сайт после каждого push
Автодеплой

Что происходит после каждого push

Вы не нажимаете ничего. Отправили изменения в GitHub, дальше площадка делает всё сама, обычно за десятки секунд.

01
УвиделVercel получил сигнал о новом коммите
02
Скачалзабрал свежий код из репозитория
03
Собралопределил тип проекта и сделал готовые файлы
04
Разложилразнёс результат по серверам в разных странах
05
Обновилта же ссылка теперь показывает новую версию
Черновая ссылкана каждую ветку выдаётся отдельный адрес: можно показать вариант, не трогая основной сайт.
Откат в один кликсломали новую версию, вернули предыдущую кнопкой, без правки кода.
Журнал сборкиесли сборка упала, видно, на каком шаге и почему. Это отдаём агенту.

Честно про бесплатное

Учебный проект бесплатно. Клиентский уже нет

Это важно узнать сейчас, а не когда придёт письмо от площадки. Обе площадки бесплатны для личных и учебных проектов, и обе ограничивают коммерческое использование.

GitHub Pages

Правилами запрещены коммерческие сайты и сервисы: интернет-магазины, продажа услуг, приём платежей и работа с чувствительными данными.

Подходит: личная страница, портфолио, документация, учебный проект.

Vercel

Бесплатный тариф только для личного некоммерческого использования. Коммерческим считается даже случай, когда вам заплатили за создание или поддержку сайта.

Появился клиент и деньги, переходите на платный тариф или другой хостинг. Это нормальные рабочие расходы.

Пока учимся, всё бесплатно. Как только появляется клиент, площадка становится статьёй расходов проекта.
Домен

Домен это человеческий адрес сайта

После деплоя площадка выдаёт технический адрес вида моя-визитка.vercel.app. Это уже полноценная рабочая ссылка. Красивый адрес покупают и подключают позже.

https://materials.neovida.ai
materialsподдомен, отдельная зона внутри бренда
neovidaимя домена, сам бренд проекта
.aiзона домена верхнего уровня
Настройки домена вслепую не трогаем: адрес легко направить не туда и потерять почту вместе с сайтом.
Приватность и секреты

Публичный репозиторий видят все, включая поисковики

Публичный или приватный

При создании репозитория вы выбираете один раз. Публичный открыт любому человеку в интернете. Приватный видите только вы и те, кого позвали.

Учебный проект без чужих данных спокойно живёт публичным
Всё, что связано с работой и клиентами, делаем приватным
Публикация в GitHub Pages с приватного репозитория требует платного тарифа

Что не кладут в код никогда

Ключи и токены сервисов, они же деньги на вашем счету
Банковские данные и реквизиты
Телефоны, адреса и переписки реальных клиентов
Файл .gitignore это список того, что Git не отправит в облако. Секреты живут в нём
Один раз отправленный в GitHub ключ считается скомпрометированным навсегда. Удалить файл мало, ключ меняют.
База данных

Для первой страницы база не нужна

Статикатекст, блоки, кнопки, расчёты прямо в браузере. Этого достаточно для первого деплоя и для нашего проекта сегодня.
Базанужна, когда храним заявки, пользователей, заказы или настройки между визитами разных людей.
Стоплогин, платежи, клиентские данные и ключи не делаем быстро. Это отдельная ответственность.
Данные, которые нужны только вам, спокойно живут в браузере. Это не база, но для первой версии работает.
Практика, часть 1

Маленькая страница, чтобы пройти весь путь

Смысл не в том, чтобы сделать красиво, а в том, чтобы пройти публикацию руками. Визитку потом реально можно отправить человеку.

codex · страница-визитка
Сделай простую страницу-визитку. Только HTML, CSS и JavaScript в одной папке. Без React, без сборщиков, без backend, без базы и без ключей. На странице: моё имя [имя], одна строка чем я занимаюсь [чем], кнопка «написать мне» со ссылкой на мой Telegram [ссылка]. Сделай аккуратно и чтобы нормально смотрелось на телефоне. Сначала покажи, какие файлы создашь и зачем. Потом создай и открой страницу локально, чтобы я увидел результат.

Наш общий проект

Калькулятор заказа, который сразу выдаёт предложение

Один проект на всю группу, чтобы идти общим шагом. Дома тот же путь вы пройдёте на своём заказе из домашки.

Входпозиции заказа, количество, срок, опции. У каждого свои: тендер, партия товара, тур, комплектация, сделка.

Шаги 1-3 · Замысел, контекст, сверка

Сначала задача, потом код

codex · постановка и сверка
Я новичок, без кода, работаю в Codex. Хочу собрать: калькулятор стоимости заказа, который сразу выдаёт готовое коммерческое предложение текстом. Для кого: я и мой клиент, открывается в браузере на компьютере и телефоне. Решаем боль: считать стоимость и писать предложение руками долго, каждый раз заново. Не нужно: логин, оплата, база данных, чужие API-ключи, реальные данные клиентов. Готово, когда: ввёл позиции, увидел итоговую цену и получил текст предложения, который можно скопировать. Сначала перескажи задачу своими словами и задай мне вопросы, если что-то непонятно. Код не пиши, пока я не подтвержу.
Шаг 4 · Разведка

Почти всё уже придумано до нас

codex · разведка готовых решений
Задачу подтверждаю. Теперь сходи в интернет и найди готовые открытые решения, похожие на мою задачу: генераторы счетов и коммерческих предложений, калькуляторы стоимости. Ищи на GitHub и GitLab. Нужны живые проекты: обновлялись за последний год, есть работающее демо, свободная лицензия. Дай список из 5 штук: название, ссылка на репозиторий, ссылка на демо, сколько звёзд, когда обновлялся в последний раз. Ничего пока не скачивай и не устанавливай.

Шаг 5 · Решение

Решает человек, а не агент

codex · вытащить лучшее и собрать чертёж
Теперь собери из этих решений мой чертёж. Ответь по четырём пунктам: 1. Что я беру за основу и у кого именно (какая часть, какая логика, какой экран). 2. Что режу как лишнее для первой версии. 3. Что дописываю своё, чего нет ни в одном из них. 4. Что откладываю на потом (оплата, база, данные клиентов, интеграции). Чужой код не копируй целиком, бери идеи и структуру. Покажи чертёж списком, чтобы я подтвердил.
Шаг 6 · Первый камень

Собираем маленькими шагами

codex · сборка первой версии
Чертёж подтверждаю, начинаем собирать. Только HTML, CSS и JavaScript. Без React, без сборщиков, без backend, без базы, без логина, без платежей и без API-ключей. Данные храним в браузере. Работай маленькими шагами. После каждого шага останавливайся, коротко объясняй простыми словами, что сделал и что мне проверить. Начни с первого шага: файлы проекта и пустой экран, который открывается локально.
Проверка и публикация

Не принимаем «готово», пока не проверено

проверка
Проверь проект перед тем, как я его покажу. Пройди чек-лист: открывается ли локально, работает ли главный сценарий от начала до конца, нет ли в коде секретов и ключей, что осталось заглушкой. Дай честный отчёт: что сделано, что не доделано, где риск. Не пиши «готово», пока это не проверено.
публикация
Теперь проведи меня до публичной ссылки. Сохрани изменения через Git с понятным названием, объясни, что такое коммит на этом примере. Отправь проект в мой GitHub, скажи по шагам, что мне нажать, если нужен мой шаг руками. Опубликуй через Vercel и дай мне публичную ссылку. В конце объясни разницу: что теперь лежит в GitHub, а что открывается по ссылке.
