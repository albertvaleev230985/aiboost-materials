Главная путаница

GitHub и Vercel — не одно и то же

GitHubхранилище кода

Хранит код, историю изменений и репозиторий.

  • Показывает, какие файлы есть в проекте
  • Хранит всю commit-историю
  • Сам по себе сайт публичным не делает
Vercelпубликация сайта

Берёт код из GitHub, собирает проект и отдаёт сайт по ссылке.

  • Создаёт deployment из репозитория
  • Выдаёт публичную ссылку
  • Обновляет сайт после push в GitHub
localhost

Если ссылка начинается с localhost — её видишь только ты

Локальный черновик

localhost — это адрес проекта на твоём компьютере. Пока локальный сервер запущен, ты видишь результат в браузере.

localhost нельзя отправлять клиенту, другу или в общий чат как публичную ссылку.
У тебя открылосьэто ещё не значит, что откроется у других
Нужен запусксервер или preview работает на твоём компьютере
Публичность — позженачинается после деплоя на хостинг
Проверяем до публикациисначала локально, потом наружу
Сервер и хостинг

Чтобы сайт увидели другие, ему нужно место в интернете

Серверотдаёт сайт

Компьютер или облако, которое отдаёт сайт, когда человек открывает ссылку.

  • Должен быть включён и доступен из интернета
  • Отдаёт браузеру страницы, стили и файлы
  • Для реальных данных — аккуратная настройка
Хостингместо для сайта

Площадка, где проект размещается, собирается и становится доступен другим.

  • Vercel — удобный хостинг для web-проектов
  • После деплоя появляется публичная ссылка
  • При новых изменениях сайт обновляется
Git

Git — это история сохранений, а не облако и не сайт

git status

показывает, что изменилось в проекте

git add

выбирает изменения для сохранения

git commit

создаёт понятную точку сохранения

Commit сохраняет. Push отправляет. Deploy публикует.
Деплой

Deploy — это проверяемый выпуск, не финал навсегда

Меняешь код → сохраняешь → отправляешь в GitHub → Vercel собирает новую версию. И так по кругу, безопасно.

База данных

Для первой статической страницы база не нужна

Статикатекст, блоки, кнопки, простая логика прямо в браузере. Этого достаточно для первого деплоя.
Базанужна, когда храним заявки, пользователей, заказы или настройки между визитами.
Checkpointлогин, платежи, клиентские данные и API-ключи не делаем «по-быстрому».

Промпт для Codex

Codex должен работать маленькими шагами

codex · новый статический проект
Я новичок. Помоги создать маленький статический веб-проект для урока по хостингу. Цель: простая страница → запустить локально → сохранить в GitHub → подготовить к деплою на Vercel. Требования: простой HTML, CSS и JavaScript; без React, backend, базы, auth, платежей и API-ключей. Сначала составь план из 5–7 шагов. Потом начни с создания файлов проекта.
Проверка

Не принимаем «готово», пока не проверено

Открылось локальноесть видимый результат в браузере, а не только «файлы созданы».
Понятны измененияясно, какие файлы созданы или изменены и зачем.
Есть отчётчто сделано, что проверено и где остаётся риск.
Красивый экран ещё не доказывает, что проект работает. Сначала проверь — потом «готово».
