GitHub, Vercel и первая публичная ссылка

Здесь всё, что нужно, чтобы не путать, где живёт код, а где открывается сайт, и чтобы пройти свой проект по методу правильного старта: все промпты урока, чек-листы и словарь.

01

Главная карта маршрута

Держишь эту цепочку в голове, и GitHub с Vercel перестают быть кашей.

Идеячто хотим показать человеку.
Папка проектафайлы на компьютере: index.html, styles.css, script.js.
localhostлокальный адрес, его видите только вы, пока проект запущен на вашем компьютере.
Gitистория сохранений: status, add, commit. Точки, к которым можно вернуться.
GitHubоблачное место для кода и истории проекта. Сайт публичным сам по себе не делает.
Vercelберёт код из GitHub, собирает проект и публикует сайт.
Публичная ссылкаадрес, который уже можно отправить другому человеку.
02

Четыре слоя, которые путают чаще всего

Где сайт отдаётся, где размещается, где хранится код и кто делает публикацию.

Серверотдаёт сайт

Компьютер или облако, которое отдаёт страницу браузеру, когда человек открывает ссылку. Должен быть включён и доступен из интернета.

Хостингместо для сайта

Площадка, где проект размещается и становится доступен другим людям. Vercel и GitHub Pages это хостинги.

GitHubхранилище кода

Хранит код, историю изменений и сам репозиторий. Показывает, что и когда менялось. Публичным сайт не делает.

Vercelпубликация

Берёт код из GitHub, собирает проект и выдаёт публичную ссылку вида проект.vercel.app. Обновляет сайт после каждого push.

Commit сохраняет. Push отправляет. Deploy публикует.

У коммита есть подпись, и она должна говорить, что изменилось: «добавил кнопку написать в Telegram», а не «правки».

03

Статика простыми словами

Первая версия проекта делается статикой специально, и это защита, а не бедность.

Статический сайт это набор готовых файлов. Сервер отдаёт их человеку как есть и ничего не вычисляет. Аналогия: статика это распечатанное меню, его печатают один раз и показывают всем одинаковое. Динамика это повар, который готовит блюдо под конкретный заказ.

index.htmlтекст и структура страницы
styles.cssвнешний вид: цвета, отступы, шрифты, поведение на телефоне
script.jsлогика и реакция на действия, работает уже в браузере посетителя

Что из этого следует

Все посетители видят одно и то же, персонально ничего не меняется.
Между визитами ничего не хранится, кроме того, что осталось в браузере самого человека.
Нет личных кабинетов и общей базы, потому что хранить негде.
Для первой версии это плюс: нечему утечь и нечего сломать.

Что такое сборка

Пока проект это три файла, его отдают как есть. Как только появляются React, Next или Vite, исходники браузеру не скормишь: их сначала надо собрать, то есть превратить в готовые файлы. Vercel определяет тип проекта и делает это сам, GitHub Pages не умеет.

04

GitHub Pages против Vercel

Оба хостинга бесплатные для учёбы. Разница в том, что они умеют.

Что сравниваемGitHub PagesVercel
Что умеет раздаватьтолько готовую статикустатику и проекты со сборкой
Кто собирает проектникто, либо настраиваете самиопределяет тип и собирает сам
Обновление после правкидо 10 минут, около 10 сборок в часавтоматически на каждый коммит
Черновая версиянет, сайт одинсвоя ссылка на каждую ветку
Откат назадруками через историюкнопкой на прошлую версию
Серверная частьнет вообщеесть функции
Размер и трафиксайт до 1 ГБ, около 100 ГБ в месяцоколо 100 ГБ в месяц на бесплатном
Свой доменможноможно
Честно про бесплатное. GitHub Pages правилами запрещает коммерческие сайты и сервисы. У Vercel бесплатный тариф только для личного некоммерческого использования, и коммерческим считается даже случай, когда вам заплатили за создание сайта. Появился клиент и деньги, переходите на платный тариф или другой хостинг.

Берём Vercel: он не упрётся в потолок, когда проект перестанет быть статикой, даёт черновики и откат, обновляет сайт сам.

Pages хорош, когда сайт чисто статический и всё уже лежит в GitHub.

05

GitHub Pages включается тремя кликами

Отдельный хостинг подключать не нужно, GitHub умеет раздавать статику сам.

КЛИК 01
Settingsнастройки своего репозитория, вкладка сверху
КЛИК 02
Pagesраздел в левом меню настроек
КЛИК 03
Ветка mainвыбираем ветку, папку оставляем корневую, сохраняем

Через минуту сайт открывается по адресу вида имя-пользователя.github.io/название-проекта.

Живой пример: материалы этого курса лежат именно на GitHub Pages, materials.neovida.ai.

06

Промпты метода

Порядок не меняем. На уроке идём по ним на общем проекте, дома по ним же на своём заказе: меняется только то, что в первом промпте.

Разминка · страница-визитка
codex · болванка для деплоя
Сделай простую страницу-визитку. Только HTML, CSS и JavaScript в одной папке. Без React, без сборщиков, без backend, без базы и без ключей.
На странице: моё имя [имя], одна строка чем я занимаюсь [чем], кнопка «написать мне» со ссылкой на мой Telegram [ссылка].
Сделай аккуратно и чтобы нормально смотрелось на телефоне.
Сначала покажи, какие файлы создашь и зачем. Потом создай и открой страницу локально, чтобы я увидел результат.
Шаги 1-3 · Замысел, контекст, сверка
codex · постановка и сверка
Я новичок, без кода, работаю в Codex.
Хочу собрать: [замысел одной фразой].
Для кого: [кто будет пользоваться и на чём].
Решаем боль: [что должно стать проще или быстрее].
Не нужно: логин, оплата, база данных, чужие API-ключи, реальные данные клиентов.
Готово, когда: [признак, по которому видно результат].

Сначала перескажи задачу своими словами и задай мне вопросы, если что-то непонятно.
Код не пиши, пока я не подтвержу.
Шаг 4 · Разведка
codex · поиск готовых решений
Задачу подтверждаю. Теперь сходи в интернет и найди готовые открытые решения, похожие на мою задачу.
Ищи на GitHub и GitLab. Нужны живые проекты: обновлялись за последний год, есть работающее демо, свободная лицензия.
Дай список из 5 штук: название, ссылка на репозиторий, ссылка на демо, сколько звёзд, когда обновлялся в последний раз.
Ничего пока не скачивай и не устанавливай.
Шаг 4 · Сравнение
codex · таблица сравнения
Сравни найденные решения таблицей по колонкам:
что умеет, насколько просто запустить новичку, свежесть обновлений, лицензия, что хранит и где, чего не хватает под мою задачу.
Заброшенные проекты отметь отдельно.
В конце одной фразой скажи, какое ближе всего к моей задаче и почему.
Шаг 5 · Решение и чертёж
codex · вытащить лучшее
Теперь собери из этих решений мой чертёж. Ответь по четырём пунктам:
1. Что я беру за основу и у кого именно (какая часть, какая логика, какой экран).
2. Что режу как лишнее для первой версии.
3. Что дописываю своё, чего нет ни в одном из них.
4. Что откладываю на потом (оплата, база, данные клиентов, интеграции).
Чужой код не копируй целиком, бери идеи и структуру.
Покажи чертёж списком, чтобы я подтвердил.
Шаг 6 · Первый камень
codex · сборка первой версии
Чертёж подтверждаю, начинаем собирать.
Только HTML, CSS и JavaScript. Без React, без сборщиков, без backend, без базы, без логина, без платежей и без API-ключей. Данные храним в браузере.
Работай маленькими шагами. После каждого шага останавливайся, коротко объясняй простыми словами, что сделал и что мне проверить.
Начни с первого шага: файлы проекта и пустой экран, который открывается локально.
После сборки · Проверка перед показом
codex · честный отчёт
Проверь проект перед тем, как я его покажу.
Пройди чек-лист: открывается ли локально, работает ли главный сценарий от начала до конца, нет ли в коде секретов и ключей, что осталось заглушкой.
Дай честный отчёт: что сделано, что не доделано, где риск.
Не пиши «готово», пока это не проверено.
После сборки · Публикация
codex · до публичной ссылки
Теперь проведи меня до публичной ссылки.
Сохрани изменения через Git с понятным названием, объясни, что такое коммит на этом примере.
Отправь проект в мой GitHub, скажи по шагам, что мне нажать, если нужен мой шаг руками.
Опубликуй через Vercel и дай мне публичную ссылку.
В конце объясни разницу: что теперь лежит в GitHub, а что открывается по ссылке.
Если сломалось
codex · разбор ошибки
Вот ошибка: [вставь текст ошибки] на шаге [на каком остановился].
Не переписывай проект целиком. Найди причину, объясни её простыми словами, предложи минимальную правку и покажи, что именно поменяешь.
Внеси только после моего «ок», потом проверь, что ничего не сломалось.

08

Чек-лист перед публичной ссылкой

Не публикуем на авось. Сначала простая проверка.

Проект открыт локальностраница реально видна в браузере, а не только «файлы созданы»
Понятны измененияагент объяснил, какие файлы изменил и зачем
Нет секретовв коде нет паролей, ключей, токенов, банковских данных
Есть коммитназвание объясняет смысл изменения, а не просто «fix»
GitHub открытрепозиторий содержит нужные файлы, выбран публичный или приватный осознанно
Ссылка работает у другихоткрыли с телефона и попросили открыть соседа
Стоп-сигнал. Если в проекте появляются логин, платежи, клиентские данные, база данных, API-ключи или реальные пользователи, это уже не «быстро задеплоить». Остановитесь и попросите разбор. Один раз отправленный в GitHub ключ считается скомпрометированным навсегда: удалить файл мало, ключ меняют.
09

Что сдавать после урока

Дома проходите те же промпты на своём заказе из домашки 2.

Публичная ссылкана свой проект, а не на общий калькулятор с урока
Скрин истории коммитоввидно, что сохранений несколько и у них человеческие названия
Таблица разведкичто нашли по своей задаче и что взяли за основу
Если застрялискрин, текст ошибки и шаг, на котором остановились. Это тоже нормальный результат

Формула недели: один проект, один следующий шаг, одна проверка, один понятный отчёт.

Не «весь продукт сразу».

10

Слова урока

Их не зубрят. Их узнают в работе и используют, чтобы точнее ставить задачу агенту.

Проектпапка со всеми файлами будущего сайта
localhostадрес, открытый только на вашем компьютере
Серверкомпьютер или облако, которое отдаёт сайт людям
Хостингместо, где сайт размещается и доступен другим
Gitистория сохранений проекта
Repositoryпроект вместе с историей изменений
Commitосмысленная точка сохранения
Pushотправить изменения на GitHub
Deployпубликация проекта в интернет
Previewчерновая ссылка для проверки до публикации
Productionнастоящая публичная версия проекта
Доменчеловеческий адрес сайта
Статикаготовые файлы, сервер ничего не считает
Сборкаисходники превращаются в готовые файлы
Автодеплойсайт пересобирается сам после каждого push
GitHub Pagesраздача статики прямо из репозитория
Приватный репозиторийкод видите только вы и те, кого позвали
.gitignoreсписок того, что Git не отправит в облако
Словарь выжившего в Codexполный разбор терминов: что это, где увидите, зачем и какая типичная ошибка

Пока я смотрел локально, это был localhost. Чтобы сайт увидели другие, нужен хостинг.

Код лежит в GitHub. Сайт опубликован на Vercel. Домен это красивый адрес, его подключают позже.

База не нужна, пока мы не храним данные людей.
