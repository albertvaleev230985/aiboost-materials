1

Главная карта маршрута

Держишь эту цепочку — GitHub и Vercel перестают быть кашей.

Идеячто хотим показать человеку.
Папка проектафайлы на компьютере: index.html, styles.css, script.js, README.

Gitистория сохранений: status → add → commit.

Vercelберёт код из GitHub, собирает проект и публикует сайт.
Публичная ссылкаадрес, который уже можно отправить другому человеку.
2

Сервер, хостинг, GitHub и Vercel

Разводим четыре слоя: где сайт отдаётся, где размещается, где хранится код и кто делает деплой.

Серверотдаёт сайт

Компьютер или облако, которое отдаёт сайт браузеру пользователя.

Хостингместо для сайта

Площадка, где сайт размещается и становится доступен из интернета.

GitHubхранилище кода

Хранит код, историю изменений и репозиторий. Сам по себе сайт публичным не делает.

Vercelпубликация

Берёт код из GitHub, собирает проект и выдаёт публичную ссылку вида project.vercel.app.

3

Промпт для Codex

Вставь целиком. Он специально ограничивает проект, чтобы не улететь в backend, базы и платежи.

codex · маленький статический проект
Я новичок. Помоги мне создать маленький статический веб-проект для урока по хостингу.

Цель: сделать простую страницу, запустить её локально, сохранить в GitHub и подготовить к деплою на Vercel.

Требования:
- используй простой HTML, CSS и JavaScript;
- не используй React, Vite, backend, базу данных, auth, платежи и API-ключи;
- работай маленькими шагами;
- после каждого шага объясняй простыми словами, что изменилось;
- перед деплоем проверь, что проект открывается локально;
- если нужен мой шаг в GitHub или Vercel, дай инструкцию в 1-3 действия.

Сначала составь план из 5-7 шагов. Потом начни с создания файлов проекта.
4

Фразы для работы с Codex

Когда проект уже создан — эти команды помогают не принимать «готово» вслепую.

codex · проверка и подготовка к деплою
Сделай первую статическую версию без backend и базы.

Покажи, какие файлы изменились, и объясни простыми словами.

Проверь локально и скажи, что именно подтверждает результат.

Перед git pull сначала проверь статус, потом подтяни изменения безопасно.

Я не понимаю ошибку. Объясни её бытовым языком и предложи минимальный фикс.

Подготовь проект к деплою на Vercel, но не добавляй auth, базу, платежи и API-ключи.
5

Чек-лист перед публичной ссылкой

Не публикуем «на авось». Сначала простая проверка.

Проект открыт локальностраница реально видна в браузере, не только «файлы созданы».
Понятны измененияCodex объяснил, какие файлы изменил и зачем.
Нет секретовв коде нет паролей, API-ключей, токенов, банковских данных.
Есть commitназвание объясняет смысл изменения, а не просто «fix».
GitHub открытрепозиторий содержит нужные файлы проекта.
Vercel дал ссылкупубличная ссылка открывается не только у тебя.
Стоп-сигнал: если появляются логин, платежи, клиентские данные, база данных, API-ключи или реальные пользователи — это уже не «быстро задеплоить». Остановись и попроси разбор.
6

Что сдавать после урока

Нужны следы работы, по которым понятно, где проект и где он застрял.

Если получилосьссылка Vercel, ссылка GitHub и 3 предложения «что где живёт».
Если не получилосьскрин или текст места, где застрял, и полный текст ошибки.
Названия commitнапиши 3 нормальных названия сохранений для своего проекта.
Идея улучшенияодна маленькая идея, что добавить в проект дальше.
